# 霜月十五张原型与测试规则

这是供实现和首轮测试使用的v0.1提案。霜蚀6层、超然2个自身回合结束、月痕8层、月蚀4点伤害乘4击都是起测值，没有经过游玩验证。完整15张卡的基础效果、升级、职责与观察问题见工作簿，机器可读版本见 [prototype.json](data/prototype.json)。

## 玩家与敌人资源

霜蚀只属于玩家，跨回合保留，战斗结束清除。普通状态中获得霜蚀后立即检查阈值；达到或超过阈值，清空全部霜蚀，进入超然。溢出不留存，一次获得最多触发一次。6层和超然状态不同时存在。

超然没有通用伤害倍率，也不额外增加能量。进入时抽1张牌；卡牌可以改用超然分支，月下霜等效果可以监听该状态。持续2次自身回合结束，包含触发当回合。因此T3中途进入，在T3结束后剩1，在T4结束后退出；T3临近结束才进入也消耗第一次计数。额外自身回合同样计数，敌人回合不计数。

超然期间所有霜蚀获得请求均为0，包括寒月返霜和凝霜翻倍后的请求。移除霜蚀不会提前结束超然。结束时回到普通状态，霜蚀为0；v0.1没有资源缓存或自动再入场。

月痕分别属于各敌人，跨回合保留，无自然衰减。施加到存活目标后立即检查：达到8层则先清空全部月痕，再触发1次月蚀，溢出丢弃。一次施加16层也只触发一次。目标死亡、离场或战斗结束时清除其月痕，不向其他目标转移。实现时按每位玩家记录来源，避免未来多人时互相消费标记；首轮仅验证单人。

月落在目标达到6层时可以提前清空并引爆；低于6层则只施加2层，施加后仍走正常阈值检查。引爆线按“月痕阈值减2”计算，不是独立写死的第二阈值。

## 支付生命与分支选择

自损是明确的HP支付，不被格挡、力量、虚弱、易伤或通常的伤害减免改变。它不是受到一次攻击。通用HpChanged事件可以知道生命变动，但不得伪造AttackReceived或EclipseHit事件。接入游戏时需验证底层命令是否符合这个语义，不能只靠变量名叫HpLoss。

v0.1采用非致命且必须全额支付：当前HP必须严格大于代价，才能打出需要该支付的普通分支。HP为2时，普通寒月斩和镜月不可用；超然分支不支付HP，可以用。检查在扣能量和改变牌堆之前完成，失败不会扣能量或给资源。若支付期间出现外部死亡，立即终止剩余效果。此规则是原型选择，并非对所有杀戮尖塔自损牌的描述。

只有卡牌明确写出的霜蚀获得才发生；被敌人打伤不会自动产霜。普通寒月斩和镜月种子为2 HP换2霜蚀；凝霜会把下一次产霜放大成4；寒月可不自损而返霜。记录每种来源，不能只用名义1:1评价生命效率。

一张牌在验证支付后、效果开始前快照是否处于超然，决定普通或超然分支，以及月下霜是否符合触发条件。效果按文本顺序执行。普通寒月斩若从4霜加到6，会立即进入超然、抽1，但本牌仍造成普通分支9伤害，不会中途改成两击。

## 月蚀的四击到底是什么

月蚀是单独的效果伤害序列。每次月蚀种子为4次4伤害，每击都可被目标格挡抵消；v0.1不受力量、活力、虚弱、易伤影响，避免与攻击牌同时放大同一事件。后续是否接入这些修正另开实验，不悄悄混用原生攻击命令。

每击结算后发出一个EclipseHitResolved，带本次月蚀ID、来源卡牌结算ID、目标、段号、格挡吸收量与实际HP伤害。完全被格挡的一击仍算已结算；潮汐因此仍给格挡。击杀目标的那一击算，目标死亡后的剩余击数取消，潮汐不预支未发生的段数。如果玩家在逐击反伤中死亡或战斗已结束，剩余队列停止。

例如敌人5 HP、无格挡：第一击4伤害，第二击击杀，第三四击取消。潮汐基础版共给2格挡，不是4。敌人存活且有16格挡：四击均被挡住，基础潮汐仍给4格挡。

月蚀不会发出“打出攻击牌”事件，也不触发月下霜。月下霜每张合格攻击牌至多执行一次，不按攻击段数执行；多个实例合并施加量后执行一次，避免同牌多次越阈造成规则差异。重复打出或复制打出的牌各有独立结算ID，并在各自开始时快照状态。

## 混合循环怎样闭合

v0.1采用跨窗口衔接：镜月与寒月斩积霜；进入超然后，月下霜让攻击牌额外叠月痕；超然结束后，寒月用目标遗留的月痕触发月蚀并返2霜，推进下一轮超然。

寒月的原始示例只有伤害且要求“触发月蚀”，没有自己的月痕来源，容易变成只依赖月下霜的条件牌。现在它先造成14伤害，再直接施加2月痕。仅当这次直接施加触发月蚀，才执行返还：普通分支获得2霜，超然分支抽1。超然期间不暗中产霜，也不增加第五个可累积资源。

月下霜的附加月痕在攻击牌全部效果之后执行，拥有独立来源；它触发的月蚀不满足寒月的返还条件。每次寒月最多获得一次返还。若攻击先杀死目标，则无法再加月痕；若月蚀击杀目标但战斗仍继续，寒月仍可兑现已经达成的返还。若战斗在月蚀中结束则停止剩余战斗效果。

因此玩家有真正的选择：超然期间立刻引爆换输出与抽牌，或保留6至7层月痕到普通状态，用寒月返霜。先观察这个选择是否有趣，再决定需不需要“超然结束时返霜”的新机制。

## 15张牌的分工

| 分组 | 卡牌 | 原型职责 |
|---|---|---|
| Frost 5张 | 寒月斩、凝霜、止水、冻彻、冰河断 | 产霜、倍增、减层、存量回报、变身回报 |
| Moon 5张 | 新月、弦月、满月、月落、潮汐 | 免费一次性铺垫、攻击铺垫、集中铺垫、提前引爆、按击防御 |
| Bridge 3张 | 镜月、月下霜、寒月 | 双资源基础牌、超然转月痕、月蚀转下一轮霜蚀 |
| Utility 2张 | 整息、守夜 | 无门槛过牌、无门槛防御过牌 |

分类是主设计任务，不是只能进入某一牌组。止水在冰爆构筑中也能调节变身时点，冻彻在变身前也能防御，镜月能给月蚀牌组附带变身机会。第一版不添加专属稀有牌、遗物、药水与额外全局倍率，降低同时变化的因素。

止水必须选择0、1或2层实际移除量。它获得6+3r格挡，r为实际移除量；升级只把基础6改为9。冻彻获得4+2F格挡，F为结算时霜蚀；升级只把4改为7。凝霜的翻倍不叠加，只在成功的正数获得时消耗，回合结束失效；升级添加保留的是卡牌，不会把已安装的翻倍效果保留到下回合。

## 首轮参数与观察方法

| 参数 | 起测值 | 对照值 | 主要观察 |
|---|---:|---|---|
| 霜蚀阈值 | 6 | 5、7 | 变身频率、溢出、维持高霜的代价 |
| 超然时长 | 2次自身回合结束 | 1次 | 状态覆盖率、是否总能连打爆发牌 |
| 入场抽牌 | 1 | 0 | 空过窗口、临近回合结束的触发惩罚 |
| 月痕阈值 | 8 | 6、10 | 首次月蚀等待、敌人死前浪费的标记 |
| 月蚀每击 | 4 | 3、5 | 固定4击，仅看直接数值强度 |
| 月蚀击数 | 4 | 2击×8伤害作为等总量对照 | 潮汐等按击效果是否提供独立价值 |
| 基础自损与产霜 | 2 HP换2霜 | 1或3 HP换2霜 | 自损是否压垮多场战斗续航 |
| 月落提前量 | 阈值减2 | 阈值减1 | 引爆时点选择是否值得一张牌 |

每轮只改一个关键因素，沿用相同牌组、同批洗牌种子和敌人脚本。首轮数字比较是控制实验，不是宣称玩家策略固定。升级先全部关闭，再单独加入凝霜保留和月落降费；否则无法分辨基础循环与升级效果。

几个可手算的起点：完整月蚀16基础伤害，每8层标记约2伤害/层，但有支付能量、延迟、溢出和提前击杀成本。三个2霜支付在无倍增、无返霜时需要6 HP触发超然；凝霜可以把其中一次变成4霜，使两次支付共4 HP达到阈值。4击×4与2击×8同为16基础伤害，基础潮汐分别产生4和2格挡，才是击数价值的有效对照。这些是算术检查，不是模拟或游玩结果。

## 测试牌组和战斗脚本

共同底牌为10张：测试打击×3（1费6伤害）、测试防御×3（1费5格挡）、寒月斩×2、弦月×1、镜月×1。这两个测试占位牌不计入15张原创牌，也不声称等同于当前游戏某角色的原生牌。

| 测试包 | 在共同10张上加入5张 | 想验证的问题 |
|---|---|---|
| 冰爆 | 凝霜、止水、冻彻、冰河断、整息 | 能否决定变身时点，HP投入是否换来足够收益 |
| 月蚀 | 新月、满月、月落、潮汐、整息 | 是否值得集中标记，提前引爆是否有决策价值 |
| 混合 | 月下霜、寒月、冰河断、月落、整息 | 能否看到跨窗口回补，是否依赖能力先上手 |
| 控霜 | 止水×2、冻彻×2、守夜 | 是否主动选择留在4至5层，而非只是摸不到变身牌 |

测试规格为70最大HP、3能量、每回合抽5、手牌上限10。第一轮不加遗物和药水，战斗间不自动回血；敌人和玩家格挡在各自回合开始清理。下列是待实现的人工敌人脚本，不是游戏原生怪物数据。

| 场景 | 脚本 | 用途 |
|---|---|---|
| 持续压力 | 单敌90 HP，每回合攻击10 | 观察基础节奏与防御成本 |
| 短命双敌 | 两敌各40 HP，每只每回合攻击5 | 观察分散标记损失与击杀后的取消段数 |
| 防御后爆发 | 单敌120 HP，奇数回合获得12格挡，偶数回合攻击22 | 观察留霜、保留标记和爆发窗口选择 |

先每组牌组在每种场景做5个固定种子，共60场，记录操作与决策原因；这是执行建议，目前0场实测。再选表现接近的参数做配对扩样。60场只能筛出明显问题，不能报告可靠的总体胜率或“最优参数”。将持续压力场景串联3场、不治疗重置，以暴露单场测试可能掩盖的生命损耗。

## 日志与晋级条件

每次事件记录run_id、seed、回合、card_instance_id、play_id、父事件ID、来源、目标、升级状态、分支快照、HP/格挡/能量/霜蚀/月痕前后值、进入或退出超然、月蚀各击结果和取消原因。快照、实际变动和请求量分别保存，才能发现“请求了产霜但实际被拒绝”的问题。

首轮关注每场自损、首次超然/月蚀回合、超然覆盖的实际出牌机会、霜蚀与月痕溢出、各来源资源贡献、月蚀实际击数、完全被格挡的击数、关键牌无效使用次数、手牌上限导致的抽牌浪费。控霜额外记录玩家在可以进超然时选择不进的次数及原因。

进入30至40张扩展阶段前，至少满足：三条主要循环都能在固定牌组中反复观察到；混合牌有能说明原因的选择价值；控霜同时出现值得保留高层数和值得突破阈值的局面；无免费自激发循环；所有支付与死亡边界符合下表。具体胜率门槛等取得实际数据后再定。

| 边界用例 | 预期行为 |
|---|---|
| 4霜，普通寒月斩 | HP-2，霜蚀清零，入超然抽1，本牌仅9伤害 |
| 5霜，再获得4霜 | 清零并入超然，3层溢出不保留 |
| 超然中请求+2霜 | 实得0；不刷新超然，不消耗未成功触发的凝霜 |
| 0霜使用止水 | 只能选移除0，得到6格挡 |
| 5霜选择止水移除1 | 剩4霜，得到9格挡；之后有机会重新进5层 |
| 7月痕再施4 | 只引爆1次，月痕归零，不留3层 |
| 5月痕使用月落 | 加到7，不提前引爆 |
| 6月痕使用月落 | 清空，引爆1次 |
| 两击攻击配月下霜 | 全牌结束后只施1次附加月痕 |
| 寒月的直接标记未引爆，月下霜才引爆 | 不给寒月返霜或抽牌 |
| 目标5 HP，月蚀4×4 | 只结算2击，潮汐基础版只给2格挡 |
| 当前HP=2，普通自损2牌 | 不可打出，能量和牌堆不变 |
| 超然最后一次回合结束 | 退出并清理窗口；其他来源产霜若后续发生按事件顺序处理 |

这些用例是实现的验收规格，不代表已执行的游戏测试。事件队列建议顺序串行处理，并带来源ID与递归深度诊断；深度上限只用于发现问题，不能用静默吞事件掩盖无限循环。与游戏API的映射、多人与存档恢复须在集成阶段另行验证。
